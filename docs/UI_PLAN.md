# UI plan: motion, icons, responsive voice screen, and the hub connection

Written 2026-10-12. Rule for everything here: layered on top. No existing
function, endpoint, event or pipeline step changes. Every existing screen must
keep working if the new code fails to load, so the new code is progressive
enhancement: plain CSS and one small script that is wrapped in try and catch and
adds a class (`ui-on`) to the root only after it started cleanly. All new CSS
is scoped under `.ui-on` or uses new class names.

tests). 90 images, every screen at 360, 390, 768, 1024 and 1440 px, light and
dark. The wizard's step 3 and error state are missing for some widths because
the wizard's own 30 second resend wait and hourly per number limit refused the
next run (that is the wizard working as designed).

### 1.2 CSS architecture and breakpoints

One stylesheet, frontend/style.css (1165 lines), with variables on :root, a
dark block under prefers-color-scheme and a [data-theme] override. Media
queries: max-width 600 px and 480 px only, plus prefers-reduced-motion. The
voice screen's corner buttons already scale with clamp() variables (--ctl,
--ctl-gap, --ctl-edge, --ctl-lg). Screen changes use .screen.active with the
screen-in and screen-out keyframes. The admin portal has its own admin.css with
one 700 px query.

### 1.3 Problems seen in the baseline at 360 px

- Voice screen: the gender, logout and theme buttons sit on top of the logo.
- Bottom controls are small (the end button is about 36 px), under the 44 px
  touch target.
- The transcript only exists behind the history button.
- 100vh based sizing: the mobile browser bar can cut the controls (to confirm
  on a device, not in emulation).

### 1.3b Lighthouse baseline (mobile, language screen, 2026-10-12)

Lighthouse run from the command line against a local server with the default
mobile throttling: performance 31, accessibility 98, best practices 96. First
contentful paint 11.0 s, largest contentful paint 201.7 s, total blocking time
1270 ms, layout shift 0. The one accessibility failure is landmark-one-main (the
language screen has no main landmark). The low performance score comes from
the simulated slow network loading the three.js and livekit scripts from a CDN and
the avatar assets, not from the page's own code; the budget is that none of
the three scores drops below these numbers. The one accessibility fix that
belongs to this work is wrapping the page in a main landmark.

### 1.4 Hub diagnosis (R5, done before any frontend work)

Run 2026-10-12 with the key from backend/.env (never printed).

| Probe | Result |
|---|---|
| GET / | 401 Unauthorized (nginx 1.24, Ubuntu) |
| POST / , POST /mcp with key | 404 Not Found |
| POST /sse with key | 405, allow: GET, HEAD |
| any path without the key | 401 |
| GET /sse with the key | 200 text/event-stream, first event `endpoint` |
| GET /mcp | 404 |

Classification: reachable, key accepted, transport is the legacy SSE transport
at /sse. There is no streamable HTTP endpoint, so the curl probes in the brief
(POST to / and /mcp) fail by design. Two things were wrong:

1. An MCP client registration that used the streamable http transport at the
   root URL could not connect. The registration must use the sse transport
   with the URL ending in /sse. Registered that way, the client connects.
2. Nothing was wrong in the app. Its client already uses the SSE transport
   with the header on every request. GET /health shows transport sse,
   reachable true, 24 tools, last_error null.

Customer data: the 24 tools contain no lookup by telephone number, name, mobile
or email and no standalone SMS tool (see docs/IMPLEMENTATION_PLAN.md 3.1). So
CUSTOMER_DATA_SOURCE cannot default to mcp_hub (ADR U6).

## 2. Design direction

Keep the identity: the blue (#2f6fed) to green (#43a047) pair already in the
variables, the Segoe UI stack with the Noto fallbacks, rounded cards, the soft
background glow. The logo file frontend/assets/mobitel-logo.png is used as it
is. No new brand colors: the glow and gradients below are made from --blue and
--green (and their dim variants) with alpha.

New tokens, in a new file frontend/ui/tokens.css, loaded after style.css, with
light and dark values:

    --glow-color: 47 111 237      (rgb triplet of --blue, used with alpha)
    --glow-color-2: 67 160 71     (rgb triplet of --green)
    --glow-soft: 0 0 24px rgb(var(--glow-color) / .35)
    --glow-strong: 0 0 40px rgb(var(--glow-color) / .55), 0 0 90px rgb(var(--glow-color-2) / .25)
    --grad-brand: linear-gradient(135deg, var(--blue), var(--green))
    --grad-stream: linear-gradient(90deg, transparent, rgb(var(--glow-color) / .8), rgb(var(--glow-color-2) / .8), transparent)
    --dur-fast: 120ms  --dur-med: 240ms  --dur-slow: 480ms  --dur-intro: 2200ms
    --ease-out: cubic-bezier(.22,.8,.3,1)
    --ease-in: cubic-bezier(.4,0,1,1)
    --ease-spring: cubic-bezier(.34,1.56,.64,1)
    --badge-bg, --badge-ring (soft brand tinted badge colors, dark variants)

Dark values lift the glow alpha slightly and use --blue-dim and --green-dim
from the existing dark block. Contrast of text and controls follows the
existing colors; the new colored text (badge icons, countdown) is checked with
axe and by hand against WCAG AA in both themes.

## 3. Motion spec

Animate only transform and opacity (plus filter for the glow). Nothing that
changes layout. will-change only during an animation. Everything stops under
prefers-reduced-motion: reduce (replaced by a 150 ms fade or nothing) and when
document.hidden.

| Motion | Duration | Easing | Sequence |
|---|---|---|---|
| Shape morph | 1600 ms | spline | an organic outline (SVG path, all shapes share one structure) morphs through three forms and settles into a circle; the logo scales in at 300 ms |
| Ripples | 4 x 1500 ms, 650 ms apart from 1.5 s | cubic-bezier(.2,.6,.3,1) | glowing circles scale 0.9 to 2.3 and fade, transform and opacity only |
| Greeting typing | 1500 ms from 1.4 s | steps (one per perceived character) | the line is clipped from the right and revealed; a glowing caret rides the edge; a light stream grows under it |
| Quote typing | 1100 ms from 3.1 s | steps | same, in gradient text, "Sri Lanka's No.1 Connection" |
| Subtitle | 400 ms at 4.2 s | ease-out | opacity and translateY |
| Landing exit (morph out) | 650 ms from 4.65 s | cubic-bezier(.65,0,.35,1) | the logo glides (transform) to the first screen's logo and lands on it; ripples, text and streamlines fade; the gradient fades to reveal the screen |
| Modal open | 240 ms | ease-out | backdrop opacity and blur(0 to 6px) fade, panel translateY 12px to 0 and scale .96 to 1 |
| Modal close | 150 ms | ease-in | reverse |
| Icon badge | 320 ms, 80 ms delay | ease-spring | scale .6 to 1 and fade; glow ring pulses once |
| Wizard step change | 260 ms | ease-out | outgoing slides 24px and fades, incoming slides from the other side; direction follows forward or back |
| Progress | 260 ms | ease-out | segmented bar, fill by scaleX; "1 of 3" label text |
| Button press | 90 ms | ease-out | scale .97 |
| OTP box filled | 160 ms | ease-out | border and glow lights, small scale 1.04 to 1 |
| Error shake | 300 ms | ease-out | translateX +-6px, 3 cycles (none under reduced motion) |
| Success burst | 450 ms | ease-out | check circle draws, 10 to 14 small dots fly out and fade |
| Loader | 1600 ms loop | ease-in-out | logo breathes: scale 1 to 1.06, glow opacity .4 to .9 |
| Bottom sheet | 280 ms | ease-out | translateY 100% to 0 with a backdrop fade |
| Ambience: listening | continuous | linear | ring scale driven by mic level (read from the existing level, clamped) |
| Ambience: thinking | 1400 ms loop | linear | a conic streamline arc rotates (transform: rotate) |
| Ambience: speaking | continuous | ease-out | glow opacity follows output level, with a fixed gentle pulse when no level is available |
| Mode chip change | 220 ms | ease-out | old text slides up and fades, new slides in |
| Transcript message | 220 ms | ease-out | existing bubble-in kept |

Landing sequence (changed 2026-10-13 at the owner's request; the first version
was 2.5 s): first visit in a session about 5.3 s (shape morph 0 to 1.6 s, four
glowing rings from 1.5 s, greeting typed 1.4 to 2.9 s, quote typed 3.1 to 4.2
s, subtitle 4.2 s, logo glides to the first screen 4.65 to 5.3 s). Later visits
in the same session: about 1.7 s (logo, one ring, the greeting typed fast, the
glide). Reduced motion: a static 0.7 s with one fade, no morph, rings or typing.
Typing is a clip reveal of the whole line (never split into characters) so
Sinhala and Tamil combining marks stay whole; a line wider than the screen is
scaled down to stay on one line.
Any click, tap or key skips it at once. Skipping removes the overlay; the first
screen is already underneath, so skip changes nothing in the app's state.

The text comes from new i18n keys (landing.greeting, landing.quote, landing.subtitle),
derived from the existing greeting copy ("Welcome to SLT Mobitel ..."). Language
for the landing text: the language already chosen in this browser if there is
one, else the browser language if it is si or ta, else English. Sinhala and
Tamil are split on spaces only, never into characters, so combining marks stay
whole. Background streamlines: three SVG paths with stroke-dasharray and
stroke-dashoffset animation in brand colors at low opacity; paused through
animation-play-state when the tab is hidden.

## 4. Icon system and map

One inline SVG sprite, frontend/ui/icons/sprite.svg, injected once into the
page, symbols referenced with `<use href="#i-name">`, stroke currentColor,
stroke-width 2, round caps and joins, 24 px grid. Source: Lucide (ISC licence),
only the icons used are copied, the licence text goes to docs/THIRD_PARTY.md.
Decorative icons get aria-hidden="true"; an icon that carries meaning by itself
gets role="img" and an aria-label from the i18n files.

Header badge: a 56 px circle with a soft brand tinted fill (--badge-bg), a

attributes) is unchanged.

## 5. Responsive plan

Mobile first for the new layer: base rules are for 360 px, larger layouts add
at min-width. Breakpoints: 360 (base), 480, 768, 1024, 1440. Fluid type and
spacing with clamp(). Safe area insets through env(safe-area-inset-*). Dynamic
viewport units (dvh) for full height areas, with a vh fallback line before it.
Container queries on the voice stage so the avatar and captions adapt to the
space they have.

Voice screen ("agent dashboard"):

| Width | Layout |
|---|---|
| 360 and 480 | Top bar only shows the logo (centered) and the theme toggle; no control sits on the logo. Bottom action bar (fixed, safe area aware) with three primary actions, each 44 by 44 px or larger with a short label under the icon: Captions, Mic (larger, center), End. A fourth item, More, opens a bottom sheet with the secondary actions: History, Voice and avatar (gender), Log out, Theme. The transcript is a collapsible bottom drawer opened from History (the existing history panel, restyled as a sheet on narrow screens). Avatar scales with min(70vw, 42dvh), aspect ratio kept. |
| 768 | Same bar, wider spacing; avatar larger; the history opens as a side drawer |
| 1024 and 1440 | Existing desktop layout stays (corner buttons scaled by the variables); labels become tooltips (title and an aria-label that already exist); the bar becomes the existing bottom row |
| Landscape phone (max-height 480) | Side by side: avatar left, captions and controls right; the bar becomes a vertical rail on the right |

Touch rule: every control is at least 44 by 44 px (checked by a test at 360
px). Tooltips on hover devices (@media (hover: hover)), visible labels on touch.

The chat screen, language, select and user screens already fit; they get the
tokens, the logo glow and the modal and icon work, and a check that nothing
scrolls sideways at 360 px. The admin portal gets icons and a fix only if the
test finds an overflow.

## 8. Contracts between pieces

A single global, `window.SltUi`, defined by frontend/ui/ui.js (lead owned, tiny
bootstrap that calls each module's `init` inside try and catch):

    SltUi.ready                       true once the bootstrap finished
    SltUi.icon(name, {size, label})   -> SVGElement (aria-hidden unless label is given)
    SltUi.badge(name, {tone})         -> HTMLElement (icon badge)
    SltUi.loader.show(target, {label}) -> handle; handle.hide(); label is already localized by the caller
    SltUi.modal.enhance(overlayEl, {icon, tone})   decorates an existing modal, idempotent
    SltUi.landing.run({language, skip})   resolves when the landing is done or skipped
    SltUi.dashboard.attach(screenEl)  builds the bottom bar and sheet around the existing buttons
    SltUi.dashboard.setState(name)    idle | listening | thinking | speaking | error
    SltUi.dashboard.setLevel(0..1)    microphone or output level for the ambience
    SltUi.dashboard.setMode(text)     live mode chip text

Events fired on document (all CustomEvent, bubbles false, detail small):
`slt:modal-open`, `slt:modal-close`, `slt:wizard-step` (detail {from, to,
direction}). The wizard fires them from the lead's patch only if it can do so
without changing its own logic.

i18n keys (all three languages, same placeholders): landing.greeting,
landing.subtitle, landing.skip, loader.connecting, loader.sending,
loader.verifying, loader.thinking, dashboard.more, dashboard.captions,
dashboard.mic, dashboard.end, dashboard.history, dashboard.voice, dashboard.logout,
dashboard.theme, dashboard.sound, dashboard.sheet_close, dashboard.mode, wizard.progress
("{current} of {total}"), empty.transcript, offline.title. Sinhala and Tamil are
machine written and need native speaker review.

Every module defines its own CSS file and nothing in it changes a rule outside
`.ui-on` or its own class names.

## 10. Risks

- The animation code could cost frame rate on a low phone: only transform,
  opacity and filter, measured with a trace and Lighthouse, and a
  low power fallback (no blur, no streamlines) when the device reports
  hardwareConcurrency 4 or less and deviceMemory 2 or less.
- backdrop blur is expensive on old phones: blur only on devices that pass the
  check above, a plain tint otherwise.
- The wizard and the landing both add overlays: the landing is removed from
  the DOM before the first interaction can start the wizard.
- Sinhala and Tamil strings are longer: all new labels wrap, bar labels use
  two lines and a smaller size at 360 px, checked in the tests.
- Real device behavior (iOS Safari bars, notches, Firefox) is only emulated
  here. This is said in KNOWN_LIMITATIONS.md.
- The CDN scripts (three.js, livekit-client) are already render blocking on
  the page; Lighthouse results depend on the network.

## 11. Test plan

Playwright (tests/ui, Chromium with the system Chrome channel; Firefox and
WebKit only if installed, otherwise reported as not run): screenshots at all
five widths in light, dark and reduced motion; touch targets of at least 44
px on the voice screen at 360 px; no horizontal scroll at 360 px on every
screen; axe checks (no serious or critical violations introduced against the

timeout, success. Lighthouse mobile before and after; the numbers go in
KNOWN_LIMITATIONS.md and the final report.

## 12. ADRs

- U1 No animation library. CSS plus the Web Animations API cover every motion
  here in a few KB; a library would add weight and a failure mode.
- U2 Progressive enhancement through a `ui-on` class. If the new script fails,
  no new rule applies and the old screens are untouched.
- U3 Landing is an overlay above the first screen, not a new screen, so the
  first screen's layout and the router are unchanged and skip is trivial.
- U4 Lucide (ISC) for icons, copied into one sprite, only the used icons.
- U5 Brand tokens derive from the existing variables; the logo is only used as
  the file already in the repo.
- U6 CUSTOMER_DATA_SOURCE defaults to local, not mcp_hub, because the hub has
  no customer lookup tool; the brief's default applies once it has one.
- U7 "Agent dashboard" means the voice screen; the admin portal gets icons and
  an overflow check only.
- U8 No new backend events. Ambience and the mode chip use the existing
  status, level and mode fields.
- U9 The bottom bar is built around the existing buttons (moved, not copied),
  so ids, handlers and aria state keep working.
